Gemello di `GUIDA.md` (LM) e di `docs/2026-06-22-part1b-lora.md` (LoRA), per la
**Parte 2.A**: intent classification + slot filling su ATIS, partendo dal GPT2 della
Parte 1. Obiettivo: chiarezza totale e pipeline facile da usare.

---

## 0. Il quadro generale: cosa stiamo facendo

Un assistente vocale per voli deve capire due cose da una frase come *"voglio un volo
da Boston a Denver"*:
- **intent** (cosa vuole l'utente): una **etichetta per l'intera frase** (es. `flight`)
  → *intent classification* (text classification).
- **slot** (i dettagli): una **etichetta per ogni parola** in formato IOB (es.
  `B-fromloc.city_name` su "Boston") → *slot filling* (sequence labeling).

Li impariamo **insieme** (multi-task) con un unico modello. Dataset: **ATIS** (voli).

### Glossario veloce
- **Intent classification**: una label per frase (accuracy come metrica).
- **Slot filling**: una label IOB per token. **IOB**: `B-x` inizio di uno slot di tipo
  x, `I-x` continuazione, `O` nessuno slot. Metrica: **F1 a livello di chunk** (conll).
- **conll / F1 a chunk**: lo slot è corretto solo se l'intero "pezzo" (es.
  `B-toloc.city_name I-toloc.city_name` = "new york") è esatto. Lo calcola lo script
  `conll.py` del corso. **Scala 0–1** (1.0 = perfetto); noi la mostriamo in %.
- **CLS token**: un token speciale che appendiamo **in coda** a ogni frase. Da lì
  leggiamo l'intent. Perché in coda? Il modello è **causale** (decoder-only, come GPT2):
  ogni token vede solo quelli precedenti, quindi solo l'**ultimo** token "vede" tutta
  la frase → è il punto giusto per classificare l'intero enunciato.
- **Multi-task**: un solo modello, due teste, due loss sommate.

## 1. La filosofia: pipeline NLU parallela e auto-contenuta

Come per la Parte 1.B, la Parte 2 vive in un package separato `nlu_pipeline/` che
**duplica** (non importa) il codice comune indipendente dal task — gestione config,
tracking, e il **backbone GPT2 della Parte 1**. Così la pipeline gira da sola e si
esporta pulita in `NLU/part_A`. Si riusa il riusabile, si riscrive solo lo specifico
NLU.

```
nlu_pipeline/
  data.py        [nuovo]   ATIS: Lang(+CLS), dev split stratificato, Dataset, collate
  model.py       [dup+mod] backbone GPT2 (Parte 1) + teste slot_out / intent_out
  train.py       [nuovo]   loop multi-task + eval (conll F1 + accuracy) + fit
  conll.py       [dal lab] scorer F1 a chunk (verbatim)
  config.py      [dup]     YAML + sweep (identico a lm_pipeline)
  tracking.py    [dup]     seed, run dir, metrics.json, curve (su slot_f1/intent_acc)
  experiment.py  [nuovo]   una run completa
  aggregate.py   [dup+mod] tabelle con slot_f1 / intent_acc
run_nlu.py             [nuovo]  CLI (artefatti in runs_nlu/)
nlu_pipeline_export.py [nuovo]  genera NLU/part_A
configs/nlu/           [nuovo]  base + esperimenti incrementali
```

## 2. `data.py` — i dati ATIS [nuovo]

- **`load_atis`**: legge `train.json`/`test.json` (oggetti `{utterance, slots, intent}`).
- **`stratified_dev_split`**: ATIS non ha un dev set → lo creiamo dal train, **10%
  stratificato sull'intent** (sklearn, seed fisso). Gli intent con una sola occorrenza
  restano nel train (non stratificabili).
- **`Lang`**: costruisce `word2id` (pad=0, unk, cls, poi le parole del **train**),
  `slot2id` (pad=0, le slot label, e `cls`→0 cioè ignorato), `intent2id`, e gli inversi.
  Le **parole** solo dal train; le **label** da tutto il corpus (per non avere classi
  sconosciute a test time). `Lang.from_dicts` ricostruisce i vocabolari salvati
  (inference/consegna).
- **`IntentsAndSlots`**: mappa in id e **appende il CLS in coda** (lo slot del CLS è
  `cls`→0, ignorato nella loss insieme al padding).
- **`collate_fn`**: right-padding di utterance e slot a `max_len` (PAD=0); ritorna
  `{utterances, y_slots, intents, slots_len}`. `slots_len` (lunghezza reale, CLS
  incluso) serve a localizzare il CLS e a troncare il padding in valutazione.
- **`build_dataloaders`**: `(train, dev, test, lang)` — dev = split stratificato.

---

## 3. `model.py` — il modello joint [dup + mod]

Backbone **identico alla Parte 1** (attention, feed-forward, blocchi, embedding,
maschera causale, `init_weights`), qui duplicato. La differenza è la testa:

- **`slot_out`** = `Linear(d_model, num_slots)` su **ogni** posizione → slot per token.
- **`intent_out`** = `Linear(d_model, num_intents)` sull'hidden del **CLS** (ultimo
  token reale di ogni frase, `seq_lens-1`).
- **`head_dropout`**: dropout opzionale **prima delle teste** (è lo step 2 di 2.A; con
  `dropout=0` è il baseline).

`forward(idx, seq_lens) -> (slot_logits [B,L,num_slots], intent_logits [B,num_intents])`.

---

## 4. `train.py` — training/eval multi-task [nuovo]

- **loss** = `CrossEntropy(slot) + CrossEntropy(intent)` (pesi uguali, come il lab).
  Lo slot usa `ignore_index=PAD` → padding e CLS non contano. La CE degli slot vuole
  input `(B, C, L)`, da cui il `permute(0,2,1)`.
- **`evaluate`**: decodifica gli slot per frase (troncando il CLS), costruisce le liste
  di coppie `(parola, slot)` e chiama `conll.evaluate` → **slot F1**; l'intent è
  l'accuracy degli argmax. Entrambe in **[0,1]**.
- **`fit`**: early stopping sulla **slot F1 di dev** (massimizzazione), ripristina i
  pesi migliori. Riusa `pick_device`/`_build_optimizer` (duplicati da lm_pipeline).

---

## 5. Orchestrazione, CLI, consegna

- **`experiment.py`**: una run completa (dati→modello→fit→eval). In `mode: final`
  valuta su **test**. Salva curve, `best_model.pt`, **`lang.json`** (i vocabolari,
  indispensabili a inference) e `metrics.json` (best dev slot F1/intent acc, e test).
- **`aggregate.py`**: tabelle `partA_nlu_summary.{tex,md}` con colonne dev/test slot F1
  e intent acc (in %), ordinate per dev slot F1 decrescente.
- **`run_nlu.py`**: CLI `run | sweep | aggregate | finalize | export` su `runs_nlu/`.
  La run migliore = **slot F1 di dev massima**.
- **`nlu_pipeline_export.py`** → `NLU/part_A`: copia `model.py`, `data.py`→`utils.py`,
  `train.py`→`functions.py` (import relativi riscritti in piatti), `conll.py`; genera
  `main.py` (ricostruisce `Lang` da `lang.json`, carica i pesi, stampa slot F1 + intent
  acc su test); copia il dataset.

---

## 6. Approccio incrementale (come 2.A richiede)

`configs/nlu/experiments/`:
1. `00_baseline` — sweep del **learning rate** (resto fisso).
2. `01_arch` — sweep `d_model × num_layers` (col miglior lr; `d_model` divisibile per
   `n_heads`).
3. `02_dropout` — sweep del **dropout** prima delle teste (sopra la migliore config).

Ogni modifica si tiene solo se migliora la slot F1 di dev; le altre si documentano
comunque (richiesta del report).

---

## 7. Come si esegue (sulla VM)

```bash
conda activate nlu26
python run_nlu.py sweep --config configs/nlu/experiments/00_baseline.yaml   # lr
python run_nlu.py aggregate                                                 # tabelle
# porta il miglior lr in 01_arch.yaml, poi:
python run_nlu.py sweep --config configs/nlu/experiments/01_arch.yaml
python run_nlu.py sweep --config configs/nlu/experiments/02_dropout.yaml
python run_nlu.py finalize        # ri-allena la migliore e valuta su test
python run_nlu.py export          # genera NLU/part_A (+ copia best_model.pt e lang.json)
```

Smoke locale (CPU/MPS, 1 epoca): `python run_nlu.py run --config configs/nlu/experiments/_smoke.yaml`.

## 9. Riepilogo mentale

- **data.py** prepara ATIS (vocabolari + CLS in coda). **model.py** è il GPT2 della
  Parte 1 con due teste (slot per token, intent dal CLS). **train.py** lo allena in
  multi-task (loss sommata) e lo valuta con conll (slot F1) + accuracy (intent).
- Il resto orchestra come in Parte 1 (config/sweep/tracking/CLI/export), tutto duplicato
  per auto-contenimento.
- 2.A migliora incrementalmente lr → architettura → dropout, selezionando sulla **slot
  F1 di dev** e riportando il numero finale sul **test**.
- La **Parte 2.B** (fine-tuning di GPT2/BERT pre-addestrati con sub-tokenizzazione)
  arriverà in un secondo ciclo.
