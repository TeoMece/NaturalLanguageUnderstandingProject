# Guida alla Parte 2.B (NLU) — fine-tuning di GPT2 e BERT pre-addestrati

Gemello della guida di 2.A (`docs/2026-06-24-part2a-nlu.md`). Qui non addestriamo da
zero: **adattiamo modelli pre-addestrati** (GPT2 decoder, BERT encoder) al task ATIS
intent+slot, con fine-tuning multi-task. Obiettivo: chiarezza totale.

---

## 0. Cosa cambia rispetto a 2.A

| | 2.A | 2.B |
|---|---|---|
| modello | GPT2 **da zero** | GPT2 / BERT **pre-addestrati** (HuggingFace) |
| tokenizzazione | a **parole** (1 parola = 1 token) | a **sub-token** (BPE/WordPiece) |
| intent letto da | token CLS in coda | **BERT: `[CLS]` in testa**; **GPT2: ultimo token** |
| training | from scratch, lr ~5e-4 | **fine-tuning**, lr piccolo ~3e-5 |
| sfida nuova | — | **allineare le label di slot ai sub-token** |

Il resto (task, dati ATIS, metriche intent-accuracy + slot-F1-conll, selezione su dev
slot F1, dev stratificato) è identico a 2.A.

---

## 1. La sfida: sub-tokenizzazione e allineamento delle label

I tokenizer dei modelli Transformer spezzano le parole in **sub-token** per ridurre il
vocabolario (es. "Lumpur" → "Lum" + "pur"). Ma le label di slot di ATIS sono **per
parola**. Bisogna decidere quale label dare a ogni sub-token.

Soluzione (Chen et al. 2019): **la label della parola va al PRIMO sub-token**; gli altri
sub-token della stessa parola, e i token speciali (`[CLS]`, `[SEP]`, padding), ricevono
**-100** → ignorati dalla CrossEntropy (`ignore_index=-100`). Esempio:

```
parola:     Lumpur              ->  sub-token:  Lum        pur
label slot: B-toloc.city_name        label:     B-toloc..  -100  (ignorato)
```

In **valutazione** ricostruiamo gli slot a livello di parola prendendo la predizione al
**primo sub-token** di ogni parola (la mappa sub-token→parola viene da `word_ids()` del
tokenizer fast), poi passiamo le sequenze parola-per-parola a `conll` per la F1.

---

## 2. Il modello: un wrapper, due architetture

`JointNLUTransformer` avvolge un **backbone HuggingFace** (`AutoModel.from_pretrained`)
con due teste lineari sopra le hidden states:
- `slot_out` (H → num_slots) su ogni sub-token;
- `intent_out` (H → num_intents) sul token di frase.

Il token di frase dipende dall'architettura (`intent_pool`, dedotto dal nome del modello):
- **BERT (encoder bidirezionale)**: `[CLS]` in **posizione 0** — vede tutta la frase in
  entrambe le direzioni. `intent_pool="cls_first"`.
- **GPT2 (decoder causale)**: **ultimo token reale** (posizione `sum(attention_mask)-1`,
  perché il padding è a destra) — con la maschera causale è l'unico che vede tutta la
  frase. `intent_pool="last"`. (GPT2 non ha pad nativo → `pad_token=eos_token`.)

`build_joint_model(model_name, ...)` costruisce backbone + teste e deduce `intent_pool`.

> Encoder vs decoder è il punto interessante di 2.B: BERT vede il contesto **bidirezionale**
> (utile per gli slot, dove conta anche ciò che viene dopo), GPT2 solo il passato. È il
> confronto che il lab chiede.

---

## 3. Training: fine-tuning completo

- **Tutti i parametri** del backbone sono trainabili (fine-tuning completo, non LoRA —
  LoRA era la Parte 1.B). `AdamW`, **lr piccolo** (~3e-5: un lr grande distruggerebbe i
  pesi pre-addestrati), poche epoche, gradient clipping, early stopping su **dev slot F1**.
- **loss** = `CE(slot, ignore_index=-100) + CE(intent)`.
- eval: slot F1 (conll, sugli slot ricostruiti a parola) + intent accuracy.

---

## 4. File-per-file (`nlu_pipeline_b/`)

- `data.py`        : `load_atis`/`stratified_dev_split` (come 2.A), `build_label_maps`
  (slot2id/intent2id), `get_tokenizer` (add_prefix_space per GPT2; pad=eos),
  `align_labels` (primo sub-token → label, resto → -100), `IntentsAndSlotsBERTGPT2`,
  `collate_fn` (padding + `meta` per la ricostruzione), `build_dataloaders`.
- `model.py`       : `JointNLUTransformer`, `build_joint_model`.
- `train.py`       : loop multi-task, `evaluate` (ricostruzione a parola + conll), `fit`.
- `conll.py` / `config.py` / `tracking.py` : duplicati (auto-contenimento).
- `experiment.py`  : una run; **auto-tagga il modello nel nome run** (`partB_nlu__<tag>`),
  salva `best_model.pt`, `label_maps.json`, metrics (incl. `model_name`, `intent_pool`).
- `aggregate.py`   : tabelle `partB_nlu_summary.*`.
- `run_nlu_b.py`   : CLI su `runs_nlu_b/`. `nlu_pipeline_b_export.py` → `NLU/part_B`.

---

## 5. Scegliere il modello (config)

Il modello si sceglie con `model.name` (qualsiasi id HuggingFace). La run viene salvata
come `<experiment.name>__<tag>` (tag = ultima parte di `model.name`), quindi cambiare
modello produce **automaticamente una run distinta** (niente collisioni). Esempi:
`openai-community/gpt2`, `openai-community/gpt2-medium`, `google-bert/bert-base-uncased`,
`google-bert/bert-large-uncased`.

## 6. Workflow (sulla VM)

```bash
conda activate nlu26
python run_nlu_b.py sweep --config configs/nlu_b/experiments/gpt2.yaml   # GPT2, sweep lr
python run_nlu_b.py sweep --config configs/nlu_b/experiments/bert.yaml   # BERT, sweep lr
python run_nlu_b.py aggregate                                            # confronto
python run_nlu_b.py finalize        # ri-allena la migliore e valuta su test
python run_nlu_b.py export          # genera NLU/part_B (+ best_model.pt e label_maps.json)
```

> **Pesi grandi**: il fine-tuning completo salva il modello intero (~500 MB). `*.pt` è
> gitignored → il binario va nello **zip di consegna**, non in git (git serve solo al
> codice; GitHub rifiuta file >100 MB). Costruisci lo zip dove ci sono i pesi (VM).

## 8. Riepilogo mentale

- **data.py** sub-tokenizza ATIS col tokenizer del modello e allinea le label (primo
  sub-token). **model.py** mette due teste su un backbone HF (intent da `[CLS]` per BERT,
  da ultimo token per GPT2). **train.py** fa fine-tuning multi-task e valuta ricostruendo
  gli slot a parola per conll.
- Si sceglie il modello nel config; la run si auto-tagga col modello.
- Il confronto chiave è **encoder (BERT, bidirezionale) vs decoder (GPT2, causale)**.
